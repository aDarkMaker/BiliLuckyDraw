# Frontend Architecture

## Backend bridge

Wails-generated TS bindings live in `frontend/bindings/luckydraw/internal/app/` (generated by `wails3 generate bindings`, gitignored, **do not hand-edit**). The frontend imports them as the `AppService` namespace; each method internally calls `Call.ByID(numericID, ...)` from `@wailsio/runtime`. Complex return values are JSON strings parsed client-side with `JSON.parse`.

## Events

```ts
import { Events } from '@wailsio/runtime';
```

`useLottery` subscribes to `Events.On('live:user_join', cb)`; the callback calls `GetParticipantCount` to update the participant count in real time. A 1000ms polling fallback re-checks `IsLiveLotteryRunning` + `GetParticipantCount`. The QR-code login polls `CheckQRCodeStatus` every 2000ms.

## Components

| Component | Responsibility |
| --- | --- |
| `LoginView` | QR-code login (generate QR + poll status) and Cookie login |
| `LotteryView` | Start/Stop draw buttons (theme image or CSS fallback), shows `WinnerDisplay` after drawing |
| `SettingsView` | Account info, appearance (theme/language), profile CRUD + switch, background image, watched rooms |
| `TopBar` | Profile dropdown, keyword input, winner-count stepper (1–9999), settings gear button |
| `WinnerDisplay` | Winner list (rank + username + UID) and a re-draw button |
| `Button` / `Input` / `MessageToast` | Common controls (Toast 1800ms visible + 300ms fade-out) |

## Hooks

- `useAuth`: manages login state, account info, background image, watched rooms, profile, keyword, winner count. On mount, if `IsLoggedIn` is true it calls `loadAll`. Keyword/winner-count changes are debounced 500ms then auto-saved via `SaveProfileConfig`.
- `useLottery(watchedRooms, keyword, winnerCount)`: manages draw run state, participant count, winners. `handleStartLottery` toggles start/stop; on stop it calls `StopLiveLottery` → `DrawWinners` and parses the winners.

## Theme system

`themes/index.tsx`: `THEMES = [light, dark, spring-festival, beach]`, each `{id, labelKey}`.

- `detectInitialTheme`: reads `localStorage 'luckydraw-theme'`, otherwise picks dark/light by `prefers-color-scheme`.
- On switch, sets `document.documentElement.className = 'theme-${theme}'` and persists.
- `preloadThemeBackground`: on mount, injects `<link rel="preload" as="image">` for themes with a background (beach / spring-festival), eliminating switch lag.
- `useThemeBackground`: returns the theme background for beach / spring-festival, `null` for light / dark. Priority: theme background || custom background image.
- Theme CSS: each theme dir has `variables.css` (+ optional `theme.css` frosted-glass, beach/spring-festival); imported in `main.tsx`; light uses global defaults + `theme-light` class.

## i18n

`i18n/index.tsx`: a lightweight in-house hook (no react-i18next). `Lang = 'zh' | 'en'`, default `zh`, persisted in `localStorage 'luckydraw-lang'`. `t(key, params)` supports `{{param}}` interpolation and falls back zh → key. Dictionaries are `zh.json` / `en.json`.

## App.tsx

A `View = 'lottery' | 'settings'` state machine. The background `= themeBackground || backgroundImage` is applied as an inline style with a `has-bg` class. Clicking outside the settings card (a `mousedown` on `.app-content` not within `.settings-card`) switches back to lottery.
